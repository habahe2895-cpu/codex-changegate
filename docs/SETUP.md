# Install and configure ChangeGate

This tutorial is for maintainers of a GitHub repository. It assumes Python 3.10+ and a public repository with GitHub Actions enabled.

## 1. Copy the gate

Copy `changegate/`, `.changegate.json`, and `.github/workflows/changegate.yml` onto the **default branch**. The workflow deliberately checks out code from the trusted default branch, not from a proposed PR.

## 2. Choose real human reviewers

Edit `.changegate.json` on the default branch:

```json
{
  "version": 1,
  "protected_patterns": [".changegate.json", "changegate/**", ".github/workflows/**", "infra/**"],
  "voters": ["trusted-maintainer-1", "trusted-maintainer-2"],
  "minimum_approvals": 1,
  "require_latest_commit": true,
  "allow_author_vote": false
}
```

Replace the sample usernames with actual GitHub usernames of people who have agreed to review the code. **Do not paste imaginary reviewers into a real policy.** A PR author cannot approve their own changes with the default setting. A single-maintainer project whose only voter is also the PR author will intentionally remain blocked on protected changes until a second trusted reviewer is added.

## 3. Require the gate before merging

1. In your repository, open **Settings → Rules → Rulesets** (or **Branches**, depending on your GitHub UI).
2. Create a rule targeting the default branch (e.g. `main`).
3. Enable the rule requiring status checks to pass before merge. Select the `vote-gate` check generated by **ChangeGate** once it appears in the available check list.
4. Save/enforce the rule. Confirm the ruleset is **Active**, not just Evaluate.
5. If you can, also require pull-request review in GitHub's native settings. Repository admins may still have bypass privileges depending on their rules and plan.

**Crucial:** An unsuccessful action does not itself prevent merging. Unless a branch ruleset or protection rule enforces `vote-gate`, ChangeGate is only advisory.

## 4. Test two PR scenarios

- **Unprotected change:** open a PR editing only `docs/`. Expect `vote-gate` to complete successfully and say no protected files were changed.
- **Protected change:** open a PR editing a protected file such as `changegate/check.py`. With no eligible external approvals, expect the `vote-gate` check to fail. Ask an explicitly configured trusted reviewer (who is not the PR author) to approve it. Expect the status to pass *after* that review if GitHub reruns the workflow.

Do not merge a protected PR while the required check is failing. For a reproducible checklist, see [VERIFY.md](VERIFY.md).

## 5. Troubleshooting

- **Workflow missing:** Check the Actions tab and confirm workflows are enabled. The event handler exists on your trusted default branch.
- **Check does not show as required:** Open and run at least one PR, then return to your ruleset to select the generated check name.
- **A vote is not counted:** Check the voter's exact GitHub username, latest review state, and review commit SHA. Old approvals after a push are excluded by default.
- **403 errors:** Verify the workflow has `contents: read` and `pull-requests: read`; do not grant write tokens just to read review data.
- **Maintainer locked out:** For a solo project, add a separate trusted collaborator before enforcing a self-approval ban; administrators should understand recovery and bypass options.
